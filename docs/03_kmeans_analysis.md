## 1. 指標決策:改用FQMA

> **使用程式**:`fqma_aggregate.py`。

提出自訂指標FQMA,取代原本規劃的RFM(RFM之後有機會再加回來):

- **F(Frequency)來店次數**:定義同原本Frequency,不同消費日計算,同一天多筆算一次。
- **Q(Quantity)購買商品數量**:即原本的 `ItemCount`(總購買品項列數)。已確認資料沒有數量欄位,一列=一件商品,所以Q不用額外算,直接沿用既有欄位。
- **M(Monetary)消費金額**:定義不變。
- **A(Assortment/Variety)購買商品種類數量**:計算每位顧客購買過的不重複 `ITEMID` 數量,衡量「消費廣度」,是RFM三指標沒有的資訊。 `fqma_aggregate.py`在同一次掃過原始大檔時,額外做「顧客 x 商品ID」去重來計算A。

**關於Q與F/M重疊疑慮的判定方法**:不用主觀判斷,等 `fqma_features.csv` 產出後,用①Spearman等級相關係數矩陣、②VIF(變異數膨脹因子,能抓出多變數共線性,比兩兩相關更嚴謹)兩種方法檢查。相關係數 > 0.8~0.9 或 VIF > 5~10,視為高度重疊,再決定Q要不要放進K-means特徵、或只保留當輔助描述變數。

**Recency處理**:雖然這次先不用RFM,但 `Recency` 還是會一起算出來放進 `fqma_features.csv`(計算成本很低),只是不當作這次K-means的特徵,方便之後想把R加回來時不用重新處理一次原始大檔。

## 1.1 F/Q/M/A相關性與共線性檢查結果(基於實際fqma_features.csv,286,810位顧客)

> **使用程式**:`analyze_fqma_correlation.py` | **關鍵發現**:M_Monetary偏態高達76.83;Pearson與Spearman在M vs A上差距達0.505,證實離群值扭曲Pearson判讀;Q的VIF=99.99、A=83.48,嚴重共線性,決定捨棄Q_Quantity,採用F+M+A(VIF 3.85/5.56/6.67)。

**偏態係數**:M_Monetary偏態高達76.83(最大值718萬 vs 中位數3,803,差近1900倍),F/Q/A也都右偏(6.73/5.41/3.24)。確認Pearson在這份資料上不可靠——例如 M vs A,Pearson只有0.401(看似不太相關),但Spearman高達0.906(其實幾乎同步變動),差距0.505,證實離群值嚴重扭曲了Pearson的判讀。

**Spearman相關係數矩陣**:F/Q/M/A兩兩之間都在0.845~0.995之間,全部超過「高度重疊」的0.8~0.9門檻。其中`Q_Quantity`與`A_Variety`高達0.995,幾乎完全重疊(因為顧客很少重複購買同一商品,「買了幾件」≈「買了幾種」)。

**VIF**:四個指標都放入時,Q的VIF=99.99、A=83.48,嚴重共線性。測試拿掉其中一個之後:
- 拿掉Q,留F+M+A:VIF為3.85 / 5.56 / 6.67(此為最終選擇)
- 拿掉A,留F+M+Q:VIF為4.34 / 5.70 / 7.98
- 只留F+M:VIF為3.04 / 3.04(最乾淨,但完全捨棄消費廣度資訊)

**決策**:K-means暫時採用特徵 **F_Frequency + M_Monetary + A_Variety**,捨棄Q_Quantity(與A高度重複,VIF最高)。

## 1.2 Q vs M反例檢查 + 發現AvgItemPrice是獨立訊號

> **使用程式**:此節分析為一次性檢查(篩選特定百分位區間、計算相關係數),未另存為腳本檔案 | **關鍵發現**:「Q低M高」的反例顧客確實存在(0.49%),但不影響拿掉Q的整體判斷;`AvgItemPrice`(=M/Q)跟F/Q/M/A的Spearman相關係數都很低(0.074/-0.013/0.321/-0.013),是幾乎獨立的訊號。
 
**想法**:會不會有「買得少但單價高」(Q低M高)的顧客,這種情況會不會被Q/M高相關的結論忽略掉?
 
**檢查結果**:這群「買少買貴」(Q低M高)的顧客確實存在。篩選「Q在後25%、M在前25%」的顧客,共1,393位(占全體0.49%),平均只買4~5件商品,但平均消費3萬多元、單價中位數7,229元。這證實Q與M的高相關係數(Spearman 0.912)反映的是**母體的整體傾向**,不是每個人都適用的鐵律。少數反例不影響整體判斷拿掉Q的決策(因為母體層級的共線性問題還是存在),但顯示需要另外一個欄位去捕捉「單價高低」這件事。
 
**重要發現**:`AvgItemPrice`(=M/Q)跟F/Q/M/A的Spearman相關係數分別是0.074 / -0.013 / 0.321 / -0.013,幾乎是一個獨立訊號,精準對應「顧客傾向買便宜還是昂貴商品」這個問題,而且比原始Q更乾淨(M把「件數」和「單價」兩種資訊糾纏在一起,AvgItemPrice已經把件數的影響抵消掉)。
 
**決策**:考慮把 `AvgItemPrice` 加為第4個K-means特徵,測試「F + M + A + AvgItemPrice」組合的VIF後再決定是否納入。

## 1.3 衍生比率指標探索 + 最終特徵定案

> **使用程式**:`analyze_fqma_ratios.py` | **關鍵發現**:發現兩個共線性陷阱——(1)AvgItemPrice與M同時存在會間接重建出Q,造成VIF飆到80以上的隱性共線性;(2)比率指標不能跟自己的分子/分母原始值同時放入特徵(VIF飆到100+)。最終確定特徵為F_Frequency+M_Monetary+A_per_F,VIF為4.86/5.40/1.78。

**背景**:F/Q/M/A四個基礎量兩兩相除,理論上有12種方向組合,但其中6種只是另外6種的倒數。Spearman相關係數在取倒數(單調遞減轉換)下只會變號、不會產生新資訊,所以只需要算6種「有意義方向」的比率:

- `AvgBasketValue = M/F`(平均每次消費金額)
- `AvgItemPrice = M/Q`(平均單價)
- `M_per_A = M/A`(每種商品平均花多少錢)
- `Q_per_F = Q/F`(購物籃大小,每次來店買幾件)
- `A_per_F = A/F`(每次到店的商品廣度)
- `Q_per_A = Q/A`(回購強度,每種商品平均回購幾次)

**Q_per_A(回購強度)的檢查結果**:中位數1.19,且23.8%的顧客Q_per_A剛好等於1(完全沒有回購任何商品)。這解釋了Q與A為何高度相關(0.995)——這批顧客的回購行為本來就很少。但Q_per_A本身跟F(0.656)、M(0.634)、A(0.619)相關性都不低,不算獨立訊號,建議只當描述變數,不放進K-means。

**A_per_F(到店商品廣度)的檢查結果**:跟F幾乎無關(Spearman -0.024,合理,因為分母就是F本身)、跟M(0.296)、A(0.443)也只是中度相關,是繼AvgItemPrice之後第二乾淨的候選指標。

**完整VIF比較(六種組合)**:

| 組合 | 結果 |
|---|---|
| F+M+A(基準) | 3.85 / 5.56 / 6.67 |
| F+M+A+AvgItemPrice | M=80.85、A=71.24(**嚴重共線性**) |
| F+M+A_per_F(A_per_F取代A) | 4.86 / 5.40 / **1.78**(健康) |
| F+A+A_per_F(陷阱示範) | 全部飆到100~180(**嚴重**) |
| M+A_per_F+AvgItemPrice(拿掉F) | 1.32 / 1.28 / 1.25(**最乾淨**,但失去F) |
| 全部都放(陷阱示範) | 全部更嚴重 |

**重要發現一:AvgItemPrice與M同時存在時,會間接重建出Q,造成隱性共線性。** 雖然AvgItemPrice跟A、M的兩兩相關係數不高(之前算出跟A是-0.013、跟M是0.321),但代數關係上 `AvgItemPrice = M/Q`,即 `Q ≈ M / AvgItemPrice`。因為`A`與`Q`幾乎相同(0.995),所以同時擁有`M`和`AvgItemPrice`時,等於間接就能算出`A`,三者形成繞了一圈的隱性線性組合——兩兩相關係數看不出來,但VIF正確抓到了(這是VIF比兩兩相關係數更嚴謹的具體案例)。

**重要發現二:比率指標不能跟它的分子/分母原始值同時放進同一組特徵。** `A_per_F = A/F`,如果`F`、`A`、`A_per_F`三者同時存在,log轉換後三者是完全的線性組合(log(A_per_F) = log(A) − log(F)),VIF會爆到100以上(已用陷阱組合驗證)。這條規則適用於所有這次算出來的衍生比率:採用某個比率當特徵時,不能同時保留它的分子或分母原始值。

**最終決策**:K-means特徵組合確定為 **F_Frequency + M_Monetary + A_per_F**,VIF為4.86 / 5.40 / 1.78,健康。`A_Variety`、`Q_Quantity`、`AvgItemPrice`、`Q_per_A`、`M_per_A` 都不放進K-means,但保留在資料裡當分群完成後的輔助描述變數。

**分析程式碼**:`analyze_fqma_ratios.py`,涵蓋衍生比率計算、相關係數檢查、六組VIF一次性比較(含兩組刻意示範共線性陷阱的組合)。

## 1.4 為什麼要取log:實測示範 + 極端大戶的取捨

> **使用程式**:此節所有實測示範為對`fqma_features.csv`做的一次性探索分析,未另存為腳本檔案——這是決定「要不要取log」的探索階段 | **關鍵發現**:不取log時K-means會把17位極端大戶(0.0059%)獨立成一群、且等同於單純用M_Monetary排序,證實不取log的K-means並未真正用到三維度相似度;取log後才是有意義的分群,極端大戶改用獨立的百分位門檻規則處理。

**想法**:為什麼要對F/M/A_per_F取log再標準化,不取log會怎樣?

**實測示範(K=4)**:分別用「不取log,只做StandardScaler」跟「先取log(F/M用log1p,A_per_F用log)再StandardScaler」跑K-means,比較分群結果:

- **不取log**:各群人數為56,781 / 17,541 / 212,471 / **17**。最大群占74.1%(21萬多人完全沒被區分開來),最小群只有17人,查證這17人就是M_Monetary的極端大戶(平均消費500萬元,範圍293萬~718萬)。
- **取log後**:各群人數為48,026 / 75,359 / 84,530 / 78,895,平均分布在16.7%~29.5%之間,是有意義的分群。

**推測原因**:K-means用歐式距離、目標是最小化群內平方和。`M_Monetary`原始尺度下,極端大戶跟中位數差了700多萬,這幾人貢獻的距離比其他28萬人兩兩之間的距離總和還大,演算法為了最小化整體誤差,理性選擇是把這幾人獨立成一群,代價是完全犧牲對其餘99.99%顧客的區分能力。取log把跨數量級的絕對差距,轉換成「倍數差距」,才能讓演算法把力氣花在有意義的行為差異上。

**關鍵疑慮**:這17人是真實的極端貴客,取log是否會讓這個族群「被抹掉」?

**驗證與推測**:追蹤這17人在不同k值裡的分布,K=4時16人被分進一個4.8萬人的高消費群(M範圍2,265~718萬全部混在一起),1人分到另一群;就算把群數拉高到K=8,他們16人仍被分進一個2.4萬人的高消費群,**不會自成一群**。原因是log衡量的是「倍數差異」,5萬元跟718萬元雖然絕對金額差140倍,但用log衡量的差距,並沒有大到會被K-means視為「應該獨立成群」的訊號——這證實log轉換後的K-means,天生就不是設計來抓極端離群值的工具,不管群數開多大都一樣。

**結論與決策**:用「取log前/後」來描述整個流程的分工——

- **取log前的K-means**:當作一次性的探索/診斷工具,用來確認資料裡有沒有明顯的極端值、大概是什麼量級(這次的例子是17人自成一群,占全體0.0059%)。**不直接拿這個結果當正式的極端大戶名單**。
- **正式的極端大戶名單**:改用固定的百分位門檻規則(例如M_Monetary前0.1%,可參考診斷步驟抓到的0.0059%當設定門檻時的參考值),跟`IsMember`一樣是分群完成後的輔助描述/追蹤欄位,不放進K-means的距離計算。
- **取log後的K-means**:才是正式拿去做客群分群的版本,適合回答「顧客的一般行為模式可以分成幾種」這個問題,不適合、也不該期待它同時回答「誰是我們最極端的大戶」——這是兩個不同問題,分開處理。

**額外驗證:不取log的K-means,退化成單純的排序規則**。直接比較「不取log的K-means抓出的17人」vs「單純用M_Monetary排序取前17名」,**兩組完全相同(17/17一致)**。證實在M的離群值大到主導距離計算的情況下,K-means並沒有真正用到F、M、A_per_F三維度的綜合相似度,而是退化成單純依M排序——這也是改用固定百分位門檻規則(而非依賴K-means副作用)的更根本理由:兩者找到的人一樣,但排序規則更直接、更穩定、更容易向業務端解釋。

## 2. K-means分群方法

> **使用程式**:本節為彙整1、1.1~1.4節決策的規劃總結,不是新的程式輸出。

- **特徵(已定案)**:`F_Frequency` + `M_Monetary` + `A_per_F`(=A_Variety/F_Frequency,每次到店的商品廣度),VIF為4.86 / 5.40 / 1.78。
- **轉換方式(已定案)**:`F_Frequency`、`M_Monetary` 用 `log1p`(M有1筆0值,必須用log1p避免log(0)出錯);`A_per_F` 用一般`log()`(無0值,但有<1的情況,log1p會壓縮該區間),轉換後偏態係數從6.73/76.83/2.10降到0.92/-0.08/-0.32。轉換後用StandardScaler標準化。
- 群數決定:手肘法(Elbow method)+ 輪廓係數(Silhouette score)搭配判斷,不預設群數
- 初始化:K-means++,並跑多次取最穩定結果
- **極端大戶另外用業務規則旗標處理,不靠K-means自動抓取**(見1.4節,已實測證實log轉換後K-means不會、也不該被期待自動把極端值獨立成群,不管群數多大都一樣)
- 不放入K-means、但保留當輔助描述變數:`Recency`、`Q_Quantity`、`A_Variety`、`AvgItemPrice`、`AvgBasketValue`、`Q_per_A`、`M_per_A`、`IsMember`、極端大戶旗標、會員人口變數(年齡/性別/地區/入會年資)

---

## 2.1 手肘法 + 輪廓係數:決定群數K

> **使用程式**:`elbow_silhouette.py` | **關鍵發現**:Inertia下降速度在K=5~6附近明顯趨緩;Silhouette在K=6處出現局部高點(0.329),兩個指標同時支持K=6為轉折點,結果存於`elbow_silhouette_results.csv`。

**方法**:用最終定案的特徵與轉換(`F_Frequency`、`M_Monetary` 取 `log1p`;`A_per_F` 取 `log`;再 `StandardScaler`標準化),對K=2~10分別跑K-means(K-means++初始化),記錄:

- **Inertia(群內平方和)**:衡量分群的緊密程度,用全部286,810筆資料計算。
- **Silhouette Score(輪廓係數)**:因為對286,810筆資料全量計算太慢,改用抽樣20,000筆計算(`sample_size=20000, random_state=42`),抽樣結果用來看「相對趨勢」,不追求精確到小數點後第3位的絕對值。

**結果**:

| K | Inertia | Silhouette |
|---|---|---|
| 2 | 485,158 | 0.3924 |
| 3 | 306,948 | 0.3873 |
| 4 | 251,278 | 0.3406 |
| 5 | 209,420 | 0.3176 |
| **6** | **173,562** | **0.3292** |
| 7 | 155,675 | 0.3178 |
| 8 | 141,130 | 0.3194 |
| 9 | 127,099 | 0.3073 |
| 10 | 116,367 | 0.3048 |

**判讀**:

- Inertia隨K增加持續下降(預期中),下降速度在K=5~6附近開始明顯趨緩,是手肘法建議的轉折區間。
- Silhouette在K=2、K=3最高(0.39、0.39),但分群數太少(只分2~3群),商業上難以區分出有意義的客群輪廓。
- K=6處出現一個局部高點(0.329,比K=5、K=7都高),同時Inertia的下降也在此區間開始趨緩,兩個指標同時支持這個轉折點。

**決策:K=6**,在統計合理性(Inertia趨緩+Silhouette局部高點)與商業可操作性(分群數不會太少、太籠統,也不會太細碎難以操作)之間取得平衡。K=2、K=3雖然Silhouette分數更高,但淘汰理由是分群數太粗,無法回答「顧客的行為模式可以分成幾種」這個實際問題。

**產出檔案**:
- `elbow_silhouette.py`(計算程式碼,含特徵轉換、K-means跑K=2~10、Inertia/Silhouette計算,已用實際fqma_features.csv驗證過,數字與本節記錄一致)
- `elbow_silhouette_results.csv`(K=2~10的Inertia、Silhouette原始數值)
- `elbow_silhouette_chart.html`(視覺化圖表,用於輔助判讀K值)

## 3.1 客群特徵該看算術平均、還是群中心?

> **使用程式**:`final_kmeans.py`的`get_reversed_centers()`與`verify_inverse_transform()`(還原中心計算) | **關鍵發現**:還原後的群中心普遍比算術平均低、更接近中位數(例如Cluster 4:中心36,830 vs 算術平均51,583,被拉高40%多)。

**問題**:K-means實際上是在「log轉換+標準化」後的空間裡找中心點、最小化群內平方和,所以演算法真正用來定義每一群的「中心」,活在那個轉換過的空間裡,不是原始尺度(元、次數)的算術平均。

**做法**:把K-means的中心點(標準化空間)反標準化(`乘scaler.scale_加scaler.mean_`)、再做反log轉換(`expm1`還原log1p、`exp`還原log),還原回原始尺度。

**比較結果**(還原後的群中心 vs 算術平均 vs 中位數):

|---|---|---|---|---|---|---|---|---|---|---|
| 4 | 37,590 | 36.5 | 36,830 | 4.86 | 43.3 | 51,583 | 5.43 | 33.0 | 35,674 | 5.12 |
| 3 | 50,707 | 9.4 | 17,389 | 10.82 | 10.5 | 21,868 | 11.53 | 9.0 | 16,349 | 10.43 |
| 1 | 44,920 | 6.1 | 5,265 | 4.09 | 7.0 | 6,943 | 4.47 | 6.0 | 5,044 | 4.40 |
| 0 | 58,437 | 1.7 | 3,285 | 15.76 | 1.9 | 4,099 | 17.08 | 2.0 | 3,241 | 15.00 |
| 5 | 59,843 | 1.4 | 961 | 6.03 | 1.5 | 1,176 | 6.37 | 1.0 | 975 | 6.00 |
| 2 | 35,313 | 1.3 | 351 | 1.85 | 1.4 | 578 | 2.02 | 1.0 | 338 | 1.85 |

**判讀**:還原後的中心點幾乎都比算術平均低,且非常接近中位數(例如Cluster 4:中心36,830、中位數35,674,算術平均卻是51,583,被拉高40%多)。這證實算術平均容易被群內殘餘的偏態拉高,失真;還原後的群中心(或中位數當代理)更能代表「這一群典型顧客長怎樣」。

**決策**:`final_kmeans.py`與`cluster_profile.csv`正式改用「還原後的群中心」當作每群的主要代表數字,算術平均保留當對照參考,不單獨拿算術平均當作該群的代表值。
